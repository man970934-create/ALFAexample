# Бизнес-аналитика · Альфа-Бизнес

Работающий фронтенд для хакатона: главная интернет-банка, персональная лента, подробный разбор, панель источников, контекст компании и уточняющие вопросы. Интерфейс полностью на русском. Внешние шрифты и изображения не используются.

**Это демонстрационный прототип, а не банковский сервис.** Все компании, события, аналитические заметки и ответы синтетические. Материалы в разделе «Позиция Альфа-Банка» не являются реальными публикациями, цитатами или рекомендациями банка. Источники не имеют выдуманных внешних ссылок. «Подтверждённый факт» означает подтверждение внутри учебного набора, а не проверку реальной новости.

## Запуск

Нужны Node.js **22.12+** (рекомендуется Node 24 LTS) и npm. Версии пакетов зафиксированы в `package.json` и `package-lock.json`.

Из папки проекта:

```sh
npm ci
npm run dev
```

Откройте адрес из терминала, обычно `http://127.0.0.1:5173`. По умолчанию MSW включён, `.env` для демо не обязателен. При необходимости скопируйте `.env.example` в `.env`. Рабочий Service Worker уже включён в `public/`. После обновления MSW выполните `npx msw init public --save`.

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

Последняя команда открывает production-сборку на `http://127.0.0.1:4173`. Для работы MSW нужен localhost либо HTTPS. Открытие `dist/index.html` через `file://` не поддерживается.

## Docker

```sh
docker build -t alfa-insights .
docker run --rm -p 8080:80 alfa-insights
```

Откройте `http://localhost:8080`. Многоэтапная сборка: Node → статические файлы → nginx. `nginx.conf` обеспечивает fallback на `index.html` для SPA-маршрутов и явно возвращает JSON-ошибку 503 для неподключённого `/api/`. Docker не требуется для локального запуска. Docker Engine не был доступен в среде подготовки; сам образ не запускался.

## Демосценарий

1. На главной нажмите «Открыть аналитику». Для «Северного контура» в роли финансового директора первым идёт событие о стоимости финансирования.
2. Смените роль на генерального директора: планы промышленных закупок поднимутся выше. У объяснений меняется управленческий фокус.
3. Выберите «Меридиан Трейд»: приоритет получают валютный рынок и импортная логистика. Страна ФТС не трактуется как валюта расчётов.
4. Выберите «Оптима Сервис»: депозитные возможности выходят на первый план. Событие о стоимости денег интерпретируется как вопрос размещения средств. Показан частичный результат; неизвестная выручка не равна нулю.
5. Проверьте период, тип влияния и поиск. Фильтрация выполняется обработчиком API. Запрос `металл` для производственной компании выделяет сырьевое событие. Период «За сегодня» оставляет событие от 21 октября.
6. Откройте разбор. Нажмите на «Источник события», «продукты» или другой признак под утверждением: боковая панель показывает исходный фрагмент и связанный вывод. Escape закрывает панель; фокус возвращается к исходной кнопке.
7. В разборе логистики позиция банка отсутствует: выводится «Подходящий аналитический материал не найден».
8. В чате нажмите один из трёх вопросов. Ответ зависит от компании, события и категории вопроса. Неизвестные вопросы возвращают честное ограничение деморежима. Включите «Смоделировать ошибку ответа» и проверьте повтор: вопрос не дублируется.
9. Нажмите «Обновить анализ»: API возвращает этапы, интерфейс опрашивает задачу до завершения. Проценты готовности не выдумываются. У «Оптима Сервис» результат частичный.
10. Откройте «Сценарии демонстрации» под правой колонкой: доступны ошибка ленты с повтором, пустая лента, частичный результат, запрет доступа и сбой подготовки анализа. Для повторного моделирования ошибки выберите обычный сценарий, дождитесь загрузки и верните ошибку.

Учебный срез зафиксирован на **21 октября 2026, 09:30 МСК**. Обновление запускает новый процесс на том же наборе и не создаёт видимость свежих новостей. Даты и суммы форматируются через `Intl`. Истории, задачи и оценки живут в памяти mock API до перезагрузки; это явно указано в чате. Повтор старой задачи после полной перезагрузки может вернуть 404 — запустите новый анализ. Фильтры и выбранная компания при этом сохраняются в URL.

## Маршруты и состояние

- `/` — главная с персональными событиями.
- `/analytics?companyId=manufacturing&role=cfo&period=30&impact=all&search=` — лента.
- `/analytics/insights/funding?companyId=services&role=treasurer` — прямая ссылка на разбор.
- Неизвестный URL — экран 404; неизвестный инсайт — ошибка 404 с возвратом в ленту; неизвестная компания — 403.

Компании: `manufacturing`, `trade`, `services`. Роли: `ceo`, `cfo`, `treasurer`. В URL также отражаются демонстрационный `scenario` и текущий `analysisId`. При смене компании из разбора открывается её лента: инсайт может быть нерелевантен новой компании. Старые результаты не показываются под новым контекстом.

## Архитектура

```text
React / React Router
        ↓
TanStack Query (компания + роль + фильтры + инсайт в ключах)
        ↓
src/api.ts — fetch, AbortSignal, единые ошибки
        ↓
MSW → синтетические fixtures / персонализация / задачи / сообщения
или
Настоящий HTTP API, если VITE_ENABLE_MOCKS=false
```

- `src/App.tsx` — маршруты, оболочка, выбор компании, запрос профиля.
- `src/context.tsx` — контекст текущего URL, панель бизнес-контекста, демосценарии.
- `src/pages.tsx` — главная, лента, разбор, процесс анализа и чат.
- `src/ui.tsx` — карточки, утверждения, доступная модальная панель на native `dialog`, источники, состояния загрузки и ошибок.
- `src/api.ts`, `src/types.ts` — заменяемый транспорт и структурированная модель.
- `src/mocks/data.ts` — 3 синтетические компании, 7 общих событий, 13 персональных инсайтов на каждую роль, явные ограничения.
- `src/mocks/handlers.ts` — API-фильтрация, ранжирование, демозадачи, отдельные истории по компании/событию/роли, идемпотентный повтор вопроса по `requestId`.
- `src/tokens.css`, `src/App.module.css` — общие токены и CSS Modules, адаптивность, видимый фокус, reduced-motion.
- `src/test/` — интеграционные UI-тесты и проверки API через MSW в Node.

Fixtures не импортируются компонентами. Серверные данные и результаты мутаций находятся в TanStack Query; React хранит состояние панелей, редактора вопроса и мобильного меню. HTML из источников не исполняется. Текст рендерится средствами React; внешние ссылки допускают только HTTP(S).

## Подключение настоящего API

```dotenv
VITE_ENABLE_MOCKS=false
VITE_API_BASE_URL=https://your-api.example/api
```

Vite встраивает переменные **при сборке**: после изменения пересоберите проект. В Docker передайте `--build-arg VITE_ENABLE_MOCKS=false --build-arg VITE_API_BASE_URL=https://your-api.example/api`. Для same-origin API используйте `/api` и замените соответствующий `location` nginx на `proxy_pass`. Для отдельного домена сервер должен разрешать CORS; текущий транспорт использует `credentials: same-origin`, поэтому cross-origin cookie-auth потребует согласованной серверной настройки и изменения транспорта.

При `false` MSW не запускается, fixtures не подставляются при ошибках. Настоящий сервер должен реализовать контракт ниже. Все `VITE_*` публичны: секреты и ключи LLM в них размещать нельзя.

Авторизация, проверка доступа к компании/инсайту/задаче, аудит и защита данных должны выполняться на сервере. Переключатель компаний и роли демонстрирует персонализацию и не является авторизацией. Для настоящего AI-сервиса необходимы серверные разрешения инструментов, журналирование, фильтрация входных документов и защита от prompt injection; в текущем фронтенде AI не вызывается.

## API

Все пути ниже относительны к `VITE_API_BASE_URL`; JSON в UTF-8.

| Метод | Путь                                           | Назначение                                                                                                     |
| ----- | ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| GET   | `/me`                                          | Демопользователь                                                                                               |
| GET   | `/companies`                                   | Доступные компании                                                                                             |
| GET   | `/companies/:id/profile`                       | Продукты, признаки и недостающие данные                                                                        |
| GET   | `/companies/:id/feed`                          | Параметры `role`, `period` (1/7/30), `impact` (all/risk/opportunity/mixed), `search`, `scenario` (только демо) |
| GET   | `/companies/:id/insights/:insightId`           | Подробный разбор, `role`                                                                                       |
| POST  | `/companies/:id/analyses`                      | `{ "scenario": "normal" }`, ответ 202 с задачей                                                                |
| GET   | `/analyses/:analysisId`                        | Текущее состояние и этапы                                                                                      |
| GET   | `/companies/:id/insights/:insightId/messages`  | История, параметр `role`                                                                                       |
| POST  | `/companies/:id/insights/:insightId/questions` | `{ question, role, requestId, simulateError }`; обновлённая история                                            |
| POST  | `/companies/:id/insights/:insightId/feedback`  | `{ "useful": true }`; `{ "saved": true }`                                                                      |

Ошибка: `{ "error": { "code": "UNAVAILABLE", "message": "Источник временно недоступен" } }` с подходящим HTTP-статусом. GET-запросы получают `AbortSignal` от TanStack Query. Вопрос ограничен 1000 символами, повтор использует тот же `requestId`.

Утверждение: `{ id, text, origin: "fact" | "bank" | "ai", sourceIds: string[] }`. Источник: `{ id, title, type: "news" | "bank" | "company", date, excerpt, synthetic, url? }`. Признаки компании представлены источниками типа `company`. Длинные разборы — массивы структурированных утверждений, без HTML/Markdown. Полная типизация: `src/types.ts`.

Состояния задачи: `queued`, `running`, `completed`, `partial`, `failed`; этапы: `pending`, `active`, `done`, `failed`. Отсутствующая аналитика банка — `bank: null`; неизвестная выручка — `revenue: null`; продукты — `present`/`absent`/`unknown`.

## Проверки и границы

Автоматические тесты покрывают смену компании и отсутствие старого контекста, открытие источника из утверждения, вопрос с ошибкой и повтором, изоляцию историй, повтор ошибки ленты, API-фильтры и роль, 403/404, отсутствующую аналитику, неизвестные данные и ограничение свободных вопросов. `npm run build` включает TypeScript-проверку.

Парсер новостей, реальные материалы банка, LLM, агентная система, банковский backend, настоящая авторизация и долговременное хранение не реализованы по согласованному объёму задачи. Этапы анализа и AI-ответы — заменяемая демонстрация API. Никакие материалы из PDF не использованы как реальные текущие новости или финансовые рекомендации.

Документация технологий: [Vite](https://vite.dev/guide/), [MSW](https://mswjs.io/docs/).
